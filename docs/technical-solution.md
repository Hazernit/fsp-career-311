# Техническое решение ФСП Карьера

Решение команды «311» реализует инициативу работодателя: потребность превращается в объяснимую подборку кандидатов с подтверждённой тестом категорией, затем — в адресное приглашение с зарплатой. Кандидат видит условия до общения и сам разрешает контакт. Авторы решения: Кривошеин Дмитрий Алексеевич и Ощепков Даниил Сергеевич — студенты одной учебной группы Московского Политеха. Прототип пока запускается локально через Wrangler и Docker; внешний стенд не опубликован.

Версия приложения — **1.0.2**, пакет сдачи и исходный тег — **v1.0.3-hackathon**.

## Реализованный объём

Приложение поддерживает два кабинета, регистрацию по email с подтверждением, ручной профиль с ролями и софт-скиллами, обработку и публикацию по отдельным согласиям, обязательную анкету с историей, первичное тестирование, историю результатов и PDF-профиль. Работодатель создаёт компанию и потребность, видит категорию, подтверждённые навыки, объяснения, пробелы и ограниченный бонус достижений ФСП. Он уточняет подбор фильтрами, сохраняя исходный снимок, и отправляет предложение с обязательной зарплатой от–до. Статусы синхронны для обеих сторон; контакты открываются по согласованному событию и только конкретной компании.

Дополнительно реализованы публикация вакансии из потребности и самостоятельный отклик. В обоих кабинетах есть список откликов со статусами: отправлен, просмотрен, принят или отклонён. Статус меняет только работодатель этой вакансии; окончательное решение не сбрасывается повторным откликом. Профиль без достижений ФСП полностью работоспособен. Импорт PDF, исполнение пользовательского кода, видеопрокторинг, внутренний чат, реальный ATS и реальный Keycloak не реализованы. Данные ФСП — явно обозначенный демонстрационный адаптер, поскольку организаторы не предоставили реальный API.

## Архитектура

Модульный монолит использует React 19.2.6, Vinext 1.0.0-beta.5 и TypeScript 5.9.3. Серверные API выполняются в Cloudflare Worker, хранилище — D1; SQL-схема и миграции поддерживаются Drizzle 0.45.2. Локальный запуск и Docker используют Wrangler 4.92.0 и SQLite/D1 через CPU-эмулятор того же Worker. Код домена выполняется локально и не зависит от внешних сервисов. PDF-lib 1.17.1 и fontkit 1.1.1 генерируют профили с встроенным кириллическим шрифтом.

Граница модулей разделяет интерфейс, транспорт и права, доменные механики, хранение и внешние адаптеры. База хранит исходный вариант теста, завершённый результат, подтверждённую категорию, первый снимок выдачи и разрешение пары компания—кандидат. Начальные данные создаются идемпотентным серверным действием отдельно от миграций. Полная схема и модель прав описаны в `docs/architecture.md`.

## Анкета, профиль и история

Перед каждым новым тестом кандидат сохраняет анкету: непустую отрасль, специализацию и предполагаемый грейд. Сервер сверяет последнюю собственную запись с выбранной категорией теста и сохраняет ссылку на неё в попытке. История анкет дополняется неизменяемыми записями; API её перезаписи отсутствует. Самооценка не присваивает и не меняет подтверждённый грейд. После миграции старые тесты остаются читаемыми без связи с анкетой.

Профиль содержит отдельные массивы ролей и софт-скиллов. Они отображаются как сведения, указанные кандидатом, входят в автоматический PDF и не повышают балл каталога. Поля ограничены и проверяются сервером; подтвердить грейд или достижение редактированием профиля нельзя.

## Первичный тест и категория

Охват MVP: Backend на Python и Frontend, по уровням Junior и Middle. Для каждой категории подготовлен план из шести компетенций и 12 вопросов — два на компетенцию. Банк содержит 44 семейства заданий с проверяемыми эталонами, отдельными заданиями Junior и Middle и параметрическими вариантами. Меняются числа, исходные строки, контекст, порядок вопросов и вариантов; приватный seed позволяет воспроизвести случай на сервере. Время — 10 минут.

Категория подтверждается при 75% и выше и хотя бы одном правильном ответе по каждой компетенции. Полностью продемонстрированный навык требует двух правильных ответов из двух. Пропущенные ответы ошибочны. Стаж, заявленный уровень и достижения не заменяют этот результат. При неудаче уже подтверждённый уровень сохраняется, а новый автоматически не назначается. После первого провала Middle кандидат может самостоятельно сразу попробовать Junior. Смена подтверждённой категории — через 90 дней; повтор текущей категории разрешён не чаще одного раза в 10 минут.

Параметризация сокращает пользу публикации конкретного ответа, но не скрывает метод решения. Публичный исходный код и ограниченный банк позволяют изучить семейства. Устойчивость к списыванию и равная психометрическая сложность не заявлены как доказанные. Для промышленного использования нужны расширение банка, ротация, независимая экспертная проверка, пилот с реальными людьми и подтверждающий блок для пограничных результатов.

## Объяснимый подбор

Сначала действует точный фильтр подтверждённой специализации и грейда. Все обязательные навыки должны быть показаны в тесте; их отсутствие не компенсирует спортивный результат. Открытый словарь извлекает стек и компетенции из описания потребности; явно введённый неизвестный навык сохраняется без придуманного подтверждения.

| Компонент | Максимальный вес |
| --- | ---: |
| Доля требуемых продемонстрированных компетенций | 55 |
| Результат теста | 20 |
| Соответствие отраслевого контекста | 15 |
| Совпадение заявленного стека | 5 |
| Релевантные подтверждённые достижения ФСП | 5 |

При отсутствии отраслевого контекста его компонент даёт нейтральные 7,5 балла. Бонус ФСП ограничен пятью баллами, учитывает релевантность дисциплины, место и давность. Командный результат обозначается как командный, индивидуальный вклад не выводится. Тип соревнования сам по себе не превосходит другой. Каждая рекомендация содержит компоненты балла, подтверждённую категорию, совпавшие навыки, пробелы и только заявленный стек. Балл подбора не является вероятностью найма. Версия алгоритма — `fsp-evidence-match-1.0.0`.

## Каталог по подтверждённой категории

Общий каталог сначала группирует кандидатов по подтверждённым специализации и грейду. Внутри категории балл равен **95 × результат теста / 100 + бонус ФСП**, где ФСП ограничена пятью баллами и учитывает только подтверждённые достижения по продемонстрированным компетенциям. Равенство разрешается стабильным ID. Самооценка, стаж, заявленные роли, софт-скиллы и количество технологий не добавляют баллы. Версия — `fsp-category-evidence-1.0.0`.

Это рейтинг доказательств внутри категории, а соответствие конкретной потребности рассчитывается отдельно по прежней формуле 55/20/15/5/5 и сохраняется в исходном снимке. Метрики Precision@5 и NDCG@5 ниже относятся к подбору по потребности; новая формула каталога не выдаётся за измеренное улучшение этих метрик.

## Профиль и приватность

Email и телефон не входят в ранжирование и закрытые публичные DTO. Разрешение контакта адресовано паре employerId/candidateId, появляется только при accepted приглашении или самостоятельном отклике на вакансию. Оно не распространяется на другие компании. PDF использует те же серверные проверки. Типичные email, телефоны, ссылки t.me/telegram.me и Telegram-имена в свободном тексте, включая роли и софт-скиллы, скрываются до разрешения контакта; это не полная автоматическая классификация персональных данных.

При чтении исходного снимка повторно применяются актуальные правила скрытия контактов, включая снимки предыдущей версии, без переписывания сохранённого порядка. Повторно проверяются актуальные согласия: отозвавший публикацию профиль удаляется из обнаружения и старого списка. После отзыва публикации ранее согласованный диалог сохраняется при действующем согласии на обработку. Отзыв обработки закрывает работодателям карточку и PDF и скрывает contacts в принятых приглашениях, включая разрешение после самостоятельного отклика. Пароли имеют индивидуальную соль и PBKDF2-SHA256; 100 000 итераций обусловлены пределом native WebCrypto Workers. Токены сессий случайны, хранятся хэшами и выдаются через HttpOnly/SameSite/Secure cookie. Тело JSON ограничено 64 КиБ, запросы параметризованы, сервер проверяет Origin, роль и владельца. Промышленный этап предусматривает внешний IdP/более затратный KDF, аудит и управление жизненным циклом данных.

## ФСП и почта

Шесть известных mock-fsp ID с проверочными кодами демонстрируют серверный контракт. Произвольный ID не подтверждает достижения. Все имена и результаты синтетические; этот способ не подтверждает реальную личность участника. Будущий адаптер должен получать доверенный идентификатор OIDC/Keycloak, подтверждать владение ID и читать защищённый реестр. Отсутствие истории ФСП не блокирует основной путь.

Демо-ящик подтверждения email доступен только владельцу ожидающей сессии и явно обозначен в интерфейсе. Настоящая доставка реализована через HTTP Resend при настройке RESEND_API_KEY, EMAIL_FROM и DEMO_MODE=false. Секреты не входят в репозиторий. Демонстрационный стенд не заявляет отправку настоящих писем без этой настройки.

## Проверка качества

Проверка домена охватила 4 000 вариантов и 48 000 вопросов: уникальность опций, стабильный план, эталон, воспроизводимость, пороги, приватность и политику категорий. Для вычислительных семейств ответ дополнительно пересчитывается независимо по предъявленному тексту. Пройдены девять доменных и приватностных проверок и две проверки миграций, всего 11. Миграции проверены на чистой базе и на обновлении прежней схемы с сохранением профиля, теста, исходного снимка и отклика.

На восьми отложенных синтетических потребностях и 32 профилях сравнили формулу с простым совпадением стека внутри категории. Релевантность 0–3 размечена автором по пригодности к задаче, положительными считаются 2–3. Веса зафиксированы до измерения, но профили совпадают с набором UI; отложены потребности и оценки, а не реальные люди. Внешнего независимого экспертного исследования нет.

| Метрика | Объяснимый подбор | Совпадение стека |
| --- | ---: | ---: |
| Precision@5 | 0,675 | 0,525 |
| NDCG@5 | 0,9660 | 0,6425 |

Precision использует знаменатель пять; NDCG — gain 2^relevance−1 и log₂(position+1). Восемь синтетических запросов не дают статистического доказательства рыночной эффективности.

Симуляция 1 200 профилей и 2 400 попыток дала 82,17% совпадения двух результатов в среднем. Слабые профили — 99,75%, сильные — 97%, пограничные — 49,75%. Для короткого теста пограничная зона нестабильна; это измеренное ограничение, требующее более длинного подтверждающего теста. Симуляция с заранее заданными вероятностями ответа не доказывает надёжность, справедливость и психометрическую валидность на людях.

22 интеграционных сценария пройдены без ошибок. Они проверили регистрацию и подтверждение email, роли и чужие записи, обязательную анкету и историю, отсутствие ключей теста и автопонижения, ранжирование каталога, подбор по потребности, зарплату, адресное раскрытие контактов, отзыв согласий, приватность старого снимка, отклик и статусы в обоих кабинетах. Приватностные сценарии также покрыли чужого работодателя и восстановление согласия. 24 текстовые проверки трёх PDF подтвердили скрытие email, телефона и Telegram до адресного разрешения, контакт после него и маркировку ролей/софт-скиллов как заявленных. Этот протокол проверяет извлечённый текст; внешний вид пользовательских PDF отдельно не оценивался. Тёплый прогон версии 1.0.2 внутри Docker на Linux и Node.js 24.19.0: 100 запросов при параллелизме 20: ошибок 0, p50 84,7 мс, p95 142,5 мс, p99 142,7 мс. Это наблюдение на маленькой синтетической базе localhost, не оценка производственной мощности.

Исходная разметка и результаты: `tests/matching-holdout.json`, `docs/validation-results.json`, `docs/domain-mechanics.md`, `docs/api-validation.json`, `docs/pdf-validation.json`, `docs/load-validation.json`. Интеграционный раннер — `tests/api-integration.mjs`, нагрузочный — `scripts/load-check.mjs`; они сохраняют текущие результаты в `tests/results/`. Локальный API-раннер читает эталоны из собственной файловой базы, чтобы проверить механику; публичного метода доступа к эталонам до отправки нет.

## Сквозной сценарий демонстрации

Новый участник регистрируется и подтверждает email через явно обозначенный демо-ящик. Затем заполняет профиль, даёт отдельные согласия, сохраняет анкету и проходит тест. Работодатель создаёт потребность, сравнивает исходную подборку и каталог, отправляет приглашение с зарплатой. Кандидат принимает его, и контакт открывается только этой компании. Второй путь — публикация вакансии, самостоятельный отклик и изменение статуса работодателем, видимое обеим сторонам. Основное видео пакета показывает версию 1.0.2 с голосом Microsoft Дмитрий. Дополнительный `demo-overview.mp4` сохранён как обзор предыдущего интерфейса и не демонстрирует новые функции.

## Запуск и развитие

`docker compose up --build -d` собирает Worker, применяет миграции и сохраняет SQLite в томе. При занятом порту используйте FSP_PORT=18080. Исходный запуск: npm ci, npm run build, npm run db:local, npm start. Для проверок: npm run typecheck, npm run test:domain, npm run validate и при локальном сервере npm run test:api. Точные команды и варианты окружения приведены в README.

Следующий этап — реестр ФСП/OIDC, настоящая почта, независимый пилот, калибровка банка и проверка работодателей. Концепция ATS: отдельный адаптер экспортирует кандидата и статусы согласованных контактов с журналом, идемпотентностью и проверкой разрешения; прямой экспорт закрытых телефонов до принятия запрещён. Для фиктивных компаний предусмотрены подтверждение корпоративного домена, модерация, жалобы, квоты приглашений и отзыв доступа. Эти функции описывают развитие и не выданы за реализованные.

Оригинальный код открыт по MIT. Официальные логотипы ФСП, шрифты и зависимости сохраняют свои права и лицензии. Перед сдачей фиксируются commit/tag и видео той же версии; после дедлайна функциональность не меняется до разрешённого этапа доработки.
