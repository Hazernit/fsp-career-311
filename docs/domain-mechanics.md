# Категоризация, проверка компетенций и объяснимый подбор

Реализация находится в `lib/domain/`. Доменные функции не зависят от интерфейса, базы данных и внешних сервисов. Версии: `fsp-assessment-1.0.0`, `fsp-evidence-match-1.0.0`, `fsp-synthetic-portfolio-1.0.0`.

## Проверяемые категории

| Категория | Шесть компетенций |
| --- | --- |
| Backend · Junior | Python, SQL, HTTP, Git, Algorithms, Security |
| Backend · Middle | SQL, Async, HTTP, Python, Architecture, Security |
| Frontend · Junior | HTML, CSS, JavaScript, React, Accessibility, HTTP |
| Frontend · Middle | React, TypeScript, Async, CSS, Security, Testing |

Backend MVP проверяет Python. Node.js, Java и другие серверные стеки в этом банке не подтверждаются. Резюме может содержать любые навыки, но интерфейс и подбор разделяют заявленные и проверенные компетенции. SQL подтверждает базовые знания запросов, а не администрирование конкретной СУБД.

Каждый вариант содержит 12 вопросов: по два на каждую компетенцию. Банк включает 44 семейства заданий; четыре семейства HTTP и безопасности используются в нескольких категориях. Семейства меняют числовые параметры, контекст, порядок вопросов и вариантов ответа. Генератор детерминирован по приватному seed: спорный результат можно воспроизвести на сервере. Количество параметрических вариантов не означает наличие стольких независимых психометрически откалиброванных задач.

Например, задача Python использует разные массивы и множители, но во всех вариантах проверяет фильтрацию, выражение генератора и суммирование. SQL-задачи меняют строки таблиц; эталон вычисляется по тем же описанным правилам SQL. Архитектурные вопросы проверяют соответствие индекса запросу и атомарное сохранение события outbox. Средний грейд использует отдельный план, а не только больше чисел в младших задачах.

Время — 10 минут. Перед началом сервер сохраняет приватный вариант с эталонами, API отдаёт только публичные вопросы и дату окончания. Каждый ответ выбирается из четырёх уникальных вариантов. Сервер принимает только известные ID вопроса и варианта; иностранная, просроченная или уже отправленная попытка отклоняется. Эталон и объяснение доступны только после отправки. Исполнение пользовательского кода и видеопрокторинг не входят в MVP.

## Присвоение результата

Итоговый балл — округлённая доля правильных ответов из 12. Для подтверждения категории одновременно нужны:

- не менее 75 баллов, то есть хотя бы 9 правильных ответов;
- хотя бы один правильный ответ из двух в каждой компетенции.

Если кандидат правильно ответил на 10 вопросов, но оба вопроса одной компетенции ошибочны, балл 83 не подтверждает грейд: есть существенный пробел в охвате. Компетенция считается продемонстрированной только при двух правильных ответах из двух. Один правильный ответ показывает частичное освоение и не используется как обязательный подтверждённый навык в подборе.

Неудачный тест не понижает текущий грейд. При первой неудаче Middle человек может сразу самостоятельно выбрать Junior. Смена уже подтверждённой категории разрешена через 90 дней после успешного теста; повторный тест той же категории не меняет грейд и доступен с ограничением частоты попыток на сервере. Проверка специализации входит в политику смены: нельзя обойти интервал изменением профиля.

Разбор по вопросам и компетенциям помогает подготовиться. Публикация способов решения всё равно возможна: параметризация снижает пользу копирования конкретного ответа, но не делает банк защищённым от изучения. Для эксплуатации нужны увеличение независимого банка, ротация, анализ аномалий и пилот с реальными кандидатами. Эти меры описаны как развитие, а не как реализованный прокторинг.

## Подбор

Сначала применяется обязательный фильтр: специализация и грейд должны точно совпасть с потребностью и быть подтверждены тестом. Все поля `mustHave` должны присутствовать среди продемонстрированных компетенций. Отсутствующий обязательный навык не компенсируется большим итоговым баллом или достижениями ФСП.

Описание потребности разбирается словарём английских и русских терминов. Список включает Python, SQL, HTTP/REST API, React, TypeScript, HTML, CSS, асинхронность, безопасность, доступность и другие знакомые стековые слова. Нераспознанный явно введённый навык сохраняется: система не придумывает его подтверждение. Работодатель видит и может уточнить извлечённые требования. Соответствие отрасли определяется открытым словарём контекстов.

| Компонент | Максимум | Расчёт |
| --- | ---: | --- |
| Подтверждённые компетенции | 55 | Доля требуемых навыков, продемонстрированных тестом |
| Результат теста | 20 | `20 × testScore / 100` |
| Отраслевой контекст | 15 | Совпадение отраслей потребности и описания опыта; 7,5 при отсутствии отраслевого требования |
| Заявленный стек | 5 | Доля требуемых навыков, заявленных в резюме |
| Релевантные достижения ФСП | 5 | Ограниченный суммарный бонус подтверждённых достижений |

Бонус ФСП применяется только при подтверждённой привязке и релевантной компетенции события. За первое место базово 3 балла, места 2–3 — 2, места 4–10 — 1,5, участие — 1. Достижения до года учитываются полностью, от года до трёх — с коэффициентом 0,75, старше — 0,5. Недостоверная или будущая дата не добавляет бонус. Общая надбавка никогда не превышает 5. Командный результат явно обозначается, индивидуальный вклад из него не выводится. Тип соревнования сам по себе не задаёт превосходство результата.

Каждая рекомендация объясняет подтверждённую категорию, тестовый балл, совпавшие компетенции, пробелы, только заявленные навыки, отраслевой контекст и бонус ФСП. Число — сравнительный балл модели, а не вероятность успешного найма. Алгоритм выдаёт только разрешённый набор полей и не переносит контакты из входного профиля.

## Каталог внутри категории

Общий каталог использует `fsp-category-evidence-1.0.0`. Сначала кандидаты группируются по подтверждённой специализации и грейду; внутри категории `score = 95 × testScore / 100 + achievementBonus`. Достижения дают максимум 5 баллов, только за verified-записи с достоверной датой и релевантностью продемонстрированным навыкам. При равенстве используется стабильный ID. Заявленные роли, софт-скиллы, стаж и самооценка не увеличивают score.

Баллы каталога сравнивают доказательства внутри категории. Формула под конкретную потребность 55/20/15/5/5 и её исходный снимок остаются отдельными. Метрики отложенных потребностей ниже не характеризуют новую формулу каталога.

## ФСП и синтетические профили

В MVP нет реального API реестра ФСП: организаторы не предоставили его. Демонстрационный адаптер содержит шесть известных идентификаторов с проверочными кодами. Все достижения имеют источник `mock-fsp`; интерфейс обязан показывать «демо-реестр». Произвольный идентификатор или неверный код не подтверждает привязку. Эти записи демонстрируют контракт будущего серверного адаптера и не доказывают реальную личность участника.

Стенд включает 32 явно синтетических кандидата, по восемь на категорию. Их подтверждённые навыки входят в соответствующий банк. Тестовые баллы возможны для этого плана: три полностью освоенные компетенции и по одному ответу в остальных дают 9/12 = 75; четыре — 10/12 = 83; пять — 11/12 = 92; шесть — 12/12 = 100. Контакты вымышлены и используют зарезервированный домен `.example`.

## Воспроизводимая валидация

Из корня проекта, при Node.js 24:

```sh
npm run test:domain
node --test tests/migrations.test.ts
node scripts/validate-domain.ts
```

Доменные проверки охватывают 4 000 вариантов и 48 000 вопросов: уникальность опций, воспроизводимость, неизменность охвата, наличие эталона, успешное прохождение с правильными ответами, неудачу пустых ответов, пороги, приватность, отсутствие автопонижения, политику смены категории, требования подбора и ограничения ФСП. Для вычислительных семейств эталон дополнительно проверяется независимым расчётом по тексту предъявленной задачи. Пройдены девять доменных и приватностных проверок и две проверки миграций, всего 11. Дополнительные проверки охватывают рейтинг каталога, скрытие Telegram-контактов и обновление старой схемы без потери данных.

Валидационный скрипт сохраняет фактический отчёт `docs/validation-results.json`. Восемь отложенных синтетических потребностей имеют авторскую ручную разметку 0–3 в `tests/matching-holdout.json`: 0 — существенная компетенция отсутствует, 1 — большой пробел, 2 — пригодное соответствие, 3 — сильное соответствие. Положительными считаются 2 и 3. Разметка не вычисляется из балла алгоритма, веса зафиксированы до измерения. Профили совпадают с демонстрационными: отложены потребности и оценки, а не сами люди. Это не независимая внешняя экспертиза.

| Измерение | Подбор по подтверждённым навыкам | Базовое совпадение заявленного стека |
| --- | ---: | ---: |
| Precision@5 | 0,675 | 0,525 |
| NDCG@5 | 0,9660 | 0,6425 |

Precision использует знаменатель 5; NDCG — прибыль `2^relevance − 1` и скидку `log₂(position + 1)`. Базовый алгоритм соблюдает категорию и сортирует по числу совпавших навыков резюме. Все детали выдачи и исходная разметка доступны для повторения. Восемь синтетических запросов не позволяют заявить статистически доказанную эффективность на рынке найма.

Симуляция 1 200 профилей выполняет 2 400 попыток на эквивалентных вариантах. Вероятность правильного ответа задаётся заранее: 0,28 для слабых, 0,70 для пограничных, 0,95 для сильных профилей. Совпадение результата «прошёл/не прошёл» двух вариантов — 82,17% в среднем: 99,75% для слабых, 49,75% для пограничных, 97% для сильных. Матрицы переходов сохранены в отчёте.

У пограничных профилей короткий тест нестабилен. Это ограничение измерено, а не скрыто. Такая симуляция не заменяет исследование надёжности на реальных людях и не подтверждает психометрическую валидность, устойчивость к списыванию, справедливость или качество найма. До промышленного использования нужны пилот, анализ трудности и различающей способности заданий, более длинный подтверждающий блок для пограничных результатов и независимая разметка потребностей специалистами.
